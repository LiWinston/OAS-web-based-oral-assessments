# Sprint 9 — Retrospective (26 Sep 2025)

## Reflection
**Went well**
- Early pairing between Yun Chen + Nemo on the exports/reporting bundle meant data extracts, API tweaks and UI surfaced together with minimal rework.
- Examiner workflow tickets (3.7–3.10) were swarmed by the FE/BE trio, so save-progress, rubric capture and comment libraries landed within the sprint.
- Capacity on scheduling/booking (5.x series) was front-loaded, giving QA a stable build before the client demo dry-run.

**Didn’t go well**
- Regression sweep was scoped to “what changed” and missed unaffected areas, so we still lack confidence in legacy booking/report flows.
- Deployment + runbook documentation trailed the implementation, forcing handover reviewers to reverse-engineer environment steps.
- Submission logistics (Endeavour ZIP, client comms) had no Kanban visibility, so ownership shifted late in the week.

**Improvements**
- Schedule a half-day QA blitz with rotating owners so the full user story checklist runs every sprint, not only for release features.
- Treat documentation tasks as blocking stories with definitions of done (reviewed, published) instead of checklist reminders.
- Keep submission/handover artefacts on the board (with acceptance criteria) and attach receipts/screenshots before closing.
