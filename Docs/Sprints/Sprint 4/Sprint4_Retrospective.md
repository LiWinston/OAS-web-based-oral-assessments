# Sprint 4 Retrospective

**Sprint Duration:** 9 August - 15 August 2025  

## What Went Well
Database connectivity issues were resolved efficiently through collaborative problem-solving between the DevOps and backend development teams. CSV functionality implementation exceeded initial expectations with robust data validation and comprehensive error handling capabilities. Team communication showed significant improvement during technical problem resolution sessions, with faster escalation and resolution of blocking issues.

## What Didn't Go Well
API documentation consistently lagged behind feature implementation completion, creating potential integration challenges for frontend developers. The testing team failed to actively coordinate between frontend and backend teams and did not effectively track task completion progress based on user stories, failing to serve as an effective bridge between frontend and backend development efforts. Backend workload distribution proved severely unbalanced, with Yun Chen completing approximately 75% of the development work while the other three team members (Dongqiao He, Yongchun Li, and Xiang Wang) were assigned only Epic 4 responsibilities and were unable to complete their tasks, finishing only the first three user stories.

## Impediments Identified
Database connectivity requirements created unexpected development environment complexity that affected initial development velocity. Epic scope definitions encompassed multiple user roles, creating management challenges that required architectural redesign discussions. Integration handoff procedures lacked standardization across team members, leading to inconsistent delivery timelines and quality expectations. The testing team was not sufficiently proactive in facilitating communication and coordination between development teams.

## Action Items for Next Sprint
Mandatory progress reporting will be implemented before weekly review sessions to improve visibility into development progress and potential blockers. Epic decomposition by user roles will replace functionality-based grouping to better align with development team capabilities and project timeline requirements. API documentation standards and handoff procedures will be established and enforced to ensure consistent integration support. Regular integration testing sessions will be scheduled to improve coordination between frontend and backend development teams. The testing team must significantly increase their active participation in project coordination work and establish user story-based progress tracking mechanisms to effectively bridge frontend and backend development efforts.

## Process Improvements
The team will implement structured task distribution within development teams to address workload imbalance issues identified during this sprint. Clear deliverable timelines will be established for each epic component with regular checkpoint reviews. Documentation requirements will be integrated into development completion criteria to ensure consistency across all delivered features. Communication protocols will be standardized for cross-team collaboration to improve efficiency and reduce misunderstandings. The testing team will be assigned specific coordination responsibilities with clear accountability measures.

## Resource Allocation Concerns
Backend team workload distribution requires immediate attention to ensure sustainable development velocity and prevent team member burnout. The concentration of complex development tasks with a single team member creates project risk that must be addressed through better task distribution and knowledge sharing practices. Testing team effectiveness in coordination and communication roles needs substantial improvement to support overall project success.
