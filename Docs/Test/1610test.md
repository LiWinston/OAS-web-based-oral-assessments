##  System Testing Issues Summary  

### 1. “Import Group CSV” visible in Individual Assignment creation

**Current:** The “Import Group CSV” button is still visible when creating an *Individual Assignment*.
 **Expected:** The individual assignment page should not display any group-related options.
 **Suspected cause:** Frontend.

------

### 2. Examiner CSV preview incorrectly flags existing examiners as “new”

**Current:** During preview, examiners already in the database are marked as “new examiner.”
 **Expected:** Existing examiners should be correctly recognized and not flagged as new.
 **Suspected cause:** Backend.

------

### 3. Inconsistent `if_join` values in participants table

**Current:** After creating an assignment, students and examiners have different `if_join` values.
 **Expected:** All participants should share the same default `if_join` value (e.g., 0).
 **Suspected cause:** Backend.

------

### 4. Criterion score range validation missing

**Current:** A criterion can have a minimum score not equal to 0 and a maximum not equal to 100, and still be saved.
 **Expected:** The valid score range must be enforced between 0–100.
 **Suspected cause:** Frontend.

------

### 5. Individual assignment with group weight incorrectly shows success

**Current:** Backend rejects saving individual assignments with group weights, but the frontend still shows a “Success” message.
 **Expected:** The frontend should display an error message and not a success popup.
 **Suspected cause:** Frontend.

------

### 6. Examiner assignment limit not enforced

**Current:** Even after lowering an examiner’s limit (e.g., from 3 to 2), additional slots can still be assigned (e.g., 3/2 limit).
 **Expected:** The system should prevent further assignments once the limit is reached and update the display accordingly.
 **Suspected cause:** Frontend and Backend.

------

### 7. “Assign to Student” causes page freeze after completion

**Current:** When all slots are filled and the button is clicked, the page freezes and requires a manual refresh.
 **Expected:** The action should process normally with appropriate feedback (success/failure).
 **Suspected cause:** Frontend.

------

### 8. Venue filter disappears when switching to dates without that venue

**Current:** After filtering by a venue (e.g., A) and switching to another date without that venue, the page shows “No timeslots available” and hides the filter.
 **Expected:** The venue filter should remain visible and allow users to reset to “All venues.”
 **Suspected cause:** Frontend.

------

### 9. Venue filter shows unknown dash after location names

**Current:** The venue list displays a dash after names (e.g., “Venue A –”).
 **Expected:** Venue names should be displayed cleanly without extra characters.
 **Suspected cause:** Frontend.

------

### 10. Feedback cannot be fully saved as draft

**Current:** After clicking “Save as Draft,” part of the feedback is stored but not shown, and some parts are not saved at all.
 **Expected:** All feedback content should be fully saved and displayed correctly.
 **Suspected cause:** Frontend and Backend.

------

### 11. Feedback not displayed after reopening assessment

**Current:** When an admin reopens an assessment, the examiner cannot see previously submitted feedback, even though the backend response contains it.
 **Expected:** The page should load and display the previous feedback for further editing.
 **Suspected cause:** Frontend.

------

### 12. Results can be released before examiner resubmission after reopen

**Current:** After an assessment is reopened, admins can still release results before the examiner resubmits.
 **Expected:** Releasing results should be blocked until the examiner resubmits.
 **Suspected cause:** Backend.

------

### 13. Examiner cannot rescore due to “released” status after reopen

**Current:** After reopening, the assessment remains marked as “released,” preventing examiners from editing scores.
 **Expected:** Reopened assessments should revert to an editable state until resubmission and approval.
 **Suspected cause:** Backend.
