# OAS 口语评估 · 面试专项技术细节

## 目的与范围
本文档专为技术面试准备，深入解析系统中的关键技术难点、设计模式应用、并发处理方案及架构决策。内容涵盖高并发预约、复杂排课逻辑、MIX 模式双写架构、CSV 管道设计及安全体系。

## 1. 高并发下的预约一致性保障
- **业务场景**：在热门时段（如最后一周的晚间场次），大量学生同时发起预约请求，可能导致场次“超卖”（Capacity Overselling）。
- **技术方案**：
  - **数据库级原子更新**：不依赖应用层锁（如 `synchronized` 或 `ReentrantLock`），而是利用数据库行锁特性。
  - **SQL 实现**：执行 `UPDATE slot_sessions SET capacity = capacity - 1 WHERE id = ? AND capacity > 0`。
  - **乐观锁机制**：通过 `capacity > 0` 作为更新条件（CAS 变体），返回受影响行数。若行数为 0，则抛出“场次已满”异常，回滚事务。
- **优势**：相比分布式锁（Redis Redlock），此方案在当前规模下更轻量、强一致且无网络开销。
- **代码映射**：`StudentTimeSlotServiceImpl.createBooking` 调用 `SlotSessionMapper.decreaseCapacity`。

## 2. 复杂排课算法与不可变护栏
- **排课算法**：
  - **时窗切分**：基于 `TimeSlot`（大时段）的 `startTime` 和 `endTime`，结合 `sessionDuration`（考试时长）和 `breakDuration`（间隔），通过循环算法自动切分生成多个 `SlotSession`。
  - **资源校验**：在生成过程中实时校验场地（Venue）的时间重叠，防止物理资源冲突。
- **不可变护栏（Immutability Guardrail）**：
  - **设计原则**：一旦作业状态流转为“已发布（Released）”，系统强制锁定相关的时段与场次配置。
  - **实现**：在 `update` 或 `delete` 接口中前置检查 `assignment.status`，若为发布态则直接拒绝操作。这防止了在考试进行中修改时间表导致的数据不一致。
- **代码映射**：`TimeSlotServiceImpl.generateSessions`。

## 3. MIX 模式的双写与聚合架构
- **业务难点**：混合模式（Mixed Mode）下，小组评分（Group Submission）既是独立实体，又必须实时映射到组内每个成员的个人成绩单（Individual Submission），且允许对个人进行微调。
- **架构设计**：
  - **主从联动**：以小组提交为主记录（Master）。当考官提交小组评分时，触发 `AssessmentServiceImpl` 的联动逻辑。
  - **自动扇出（Fan-out）**：系统自动查找该组所有成员，为每人创建或更新一份 `AssessmentSubmission`，将小组分值（加权后）写入个人记录。
  - **事务一致性**：整个联动过程包裹在 `@Transactional` 中，确保小组与个人成绩要么同时成功，要么同时回滚，避免数据孤岛。
- **代码映射**：`AssessmentServiceImpl.submitGroupAssessment` 及其内部的 `syncToIndividualSubmissions` 逻辑。

## 4. Canvas 兼容的 CSV 管道设计
- **设计模式**：**工厂模式（Factory Pattern）**。
  - 定义 `CsvHandler` 接口，实现 `StudentCsvHandler`、`GroupCsvHandler` 等策略类。
  - 通过 `CsvHandlerFactory` 根据导入类型（type）动态分派处理器，符合开闭原则（OCP）。
- **健壮性处理**：
  - **表头模糊匹配**：处理 Canvas 导出 CSV 中可能存在的 BOM 头或不规范空格。
  - **流式处理**：虽然目前使用 `MultipartFile`，但 Handler 设计支持 `InputStream`，为未来处理超大 CSV 文件预留了流式解析能力。
  - **ZIP 打包流**：在导出 Mixed 作业时，使用 `ZipOutputStream` 动态将两个 CSV 流（个人+小组）打包，无需落地临时文件，减少磁盘 I/O。
- **代码映射**：`CsvController`, `CsvHandlerFactory`, `GradesExportServiceImpl`。

## 5. 安全体系与自定义过滤器链
- **架构**：基于 Spring Security 的无状态 JWT 架构。
- **过滤器链（Filter Chain）**：
  1.  **XssFilter**：包装 `HttpServletRequest`，对输入参数进行 HTML 转义，防止存储型 XSS 攻击。
  2.  **RepeatableFilter**：防止表单重复提交。通过缓存请求特征（URL + Token + 参数摘要）在短时间内拦截相同请求。
  3.  **JwtAuthenticationTokenFilter**：解析 Header 中的 Token，构建 `SecurityContext`，实现无状态鉴权。
- **权限控制**：
  - **RBAC**：通过 `sys_user_role` 和 `sys_role_menu` 表控制粗粒度权限。
  - **方法级鉴权**：在敏感操作（如重置密码）使用 `@PreAuthorize` 结合自定义权限字符串。
- **代码映射**：`SecurityConfig`, `framework.config` 包下的过滤器。

## 6. 性能优化与缓存策略
- **HTTP 协商缓存**：
  - 在 `StudentResultsController` 中实现 `If-Modified-Since` 机制。
  - 客户端再次请求成绩详情时，若数据未变更（对比 `update_time`），直接返回 `304 Not Modified`，显著减少移动端/Web端的流量消耗与序列化开销。
- **异步通知解耦**：
  - 邮件发送（尤其是批量激活邮件）可能耗时较长。系统采用 `NotificationQueueService` 将邮件任务入库/入队，由独立线程或调度任务异步处理，避免阻塞主业务线程（如导入 CSV 接口的响应速度）。
