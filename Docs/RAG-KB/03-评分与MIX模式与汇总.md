# OAS 口语评估 · 评分与 MIX 模式与汇总

## 目的与范围
本文深入解析评分引擎的核心逻辑，包括动态量规（Rubric）的元数据结构与校验规则、MIX 混合模式下的数据联动机制，以及管理端成绩汇总（Consolidation）的聚合算法与告警策略。

## 1. 动态量规引擎（Rubric Engine）
### 1.1 元数据结构
系统摒弃了硬编码的评分字段，采用 JSON 存储动态量规配置，以适应不同课程的评估标准。
- **结构**：包含多个 `Criteria`（维度），每个维度包含 `weight`（权重）、`maxScore`（满分）及具体的 `Level`（分级描述）。
- **快照机制**：评分提交时，系统会将当前的量规配置快照（Snapshot）保存到 `AssessmentSubmission` 中。
  - *设计意图*：即使后续课程管理员修改了作业的量规配置，已完成的评分记录依然能正确渲染和计算，保证历史数据的不可变性与追溯性。

### 1.2 校验与计算
- **边界校验**：在保存草稿或提交时，后端会校验每个维度的输入分值是否在 `[0, maxScore]` 区间内。
- **总分计算**：
  - **Points 模式**：直接累加各维度得分。
  - **Percentage 模式**：`Σ(维度得分 * 维度权重)`。系统自动处理精度问题，保留两位小数。

## 2. MIX 模式的数据联动（Data Synchronization）
### 2.1 业务挑战
在混合模式下，考官通常针对“小组”整体表现打分，但最终成绩单必须落实到“个人”。同时，考官可能需要对组内个别表现优异/落后的学生进行微调。

### 2.2 联动逻辑（Master-Slave）
- **主记录（Group Submission）**：考官操作的主要对象。
- **从记录（Individual Submission）**：系统自动生成的衍生记录。
- **自动扇出（Auto Fan-out）**：
  - 当考官**提交**小组评分时，系统触发事务：
    1.  保存小组评分记录。
    2.  查找该组所有成员。
    3.  为每位成员创建或更新个人评分记录，将小组的各维度得分自动填充到个人的“小组分”部分。
    4.  若个人记录不存在，则自动创建并标记为 `SUBMITTED`。
- **一致性保障**：通过 `@Transactional` 确保小组与个人成绩的原子性更新，避免出现“有组分无个人分”的数据孤岛。

## 3. 管理端汇总与告警（Admin Consolidation）
### 3.1 聚合指标（Aggregation Metrics）
管理端仪表盘并非简单的 CRUD，而是基于复杂 SQL 聚合的实时报表：
- **进度统计**：`已提交 / 总预约数`，直观展示评估进度。
- **趋势分析**：按 `submission_date` 进行日/周分桶（Bucket），生成时间序列数据，帮助管理员预测峰值。

### 3.2 智能告警（Alerting）
系统自动扫描异常状态并生成告警，优先级从高到低：
1.  **MISSING_EXAMINER**（缺考官）：最严重。有学生预约了场次，但该场次未分配考官或考官已移除。
2.  **OVERDUE**（逾期）：考试时间已过，但仍未提交评分。
3.  **REOPENED**（重开）：已提交的评分被管理员打回（Reopen），需要考官重新评分。
4.  **MANUAL_OVERRIDE_PENDING**（覆盖待确认）：系统检测到成绩被手动修改，需管理员二次确认。
