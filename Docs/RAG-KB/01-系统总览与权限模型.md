# OAS 口语评估 · 系统总览与权限模型

## 目的与范围
本文概述 OAS 口语评估系统的整体架构、技术栈、各模块核心职责以及 RBAC 权限模型，并串联核心业务的数据流转。

## 架构与技术栈
- 后端：Spring Boot、Spring Security（JWT）、自定义过滤器（XSS、重复提交）、MyBatis-Plus + MyBatis XML。
- 数据访问：丰富的 Mapper 与 XML 映射；以 QueryWrapper 与批量操作为主；无 JPA。
- 领域模块：预约与场次、评分与量规、成绩汇总与发布、CSV 导入导出、通知队列、权限与账号。

## 模块职责（简要）
- 预约与场次（学生、课程管理员）：学生预约 INDIVIDUAL/GROUP/MIX；时段→场次生成；考官配岗；发布约束（完全配岗后才能发布给学生）。
- 评分与量规（考官）：草稿/提交；量规元数据与校验；总分计算（分值或百分比）；MIX 模式同时处理小组与个人提交并自动联动。
- 成绩汇总（管理端）：总览指标、趋势（日/周）、告警（REOPENED、OVERDUE、手动覆盖待处理、缺考官）。
- CSV 集成：学生/小组/考官导入与预览；导出个人/小组成绩与教师评分细节；混合作业导出 ZIP。
- 通知与审计：发布通知邮件；偏好与去重；CSV 导入历史记录保存与状态更新。
- 权限与账号：RBAC 基于数据库角色；JWT 无状态鉴权；路由放行与方法级鉴权组合。

## RBAC 权限模型（角色与能力）
- 超级管理员（SuperAdmin）：系统级管理与审计。
- 课程管理员（CourseAdmin）：作业/时段/场次配置，考官配岗与发布，CSV 导入导出，成绩汇总查看。
- 考官（Examiner）：评分草稿与提交，查看分配场次与参与学生。
- 学生（Student）：预约与变更，查看已发布成绩与反馈。

## 核心数据流（叙述）
1. 预约与场次：学生在已发布到学生的作业下选择可预约场次（容量与时间冲突校验）→ 创建预约记录（`session_student`）→ 如需改约或取消则更新并回收容量；已存在评分记录时限制取消。
2. 场次生成与配岗：课程管理员基于时段窗口（时长+间隔）生成场次（`slot_sessions`）→ 复制或分配考官（`session_examiners`）并校验场次上限与人力限制 → 未完全配岗的作业不可发布给学生。
3. 评分与 MIX：考官按量规评分（草稿/提交）→ 校验权重与分值 → 计算总分；MIX 作业同时维护小组与个人提交，提交小组评分时自动提交相关个人记录以保持一致。
4. 成绩发布与通知：发布到考官仅切换可见性；发布到学生需满足“完全配岗”，发布后入队通知；发布后数据保持不可变动的护栏（例如已发布作业的场次配置不可变）。
5. CSV 与汇总：导入学生/小组/考官，严格表头校验与激活邮件；导出个人/小组成绩（混合作业打包 ZIP）与教师评分明细；管理端总览/趋势/告警展示整体进度与风险。

## 约束与边界
- 发布不可变更：已发布的作业/场次配置通常不可再编辑，避免影响考试秩序。
- 完全配岗准入：发布到学生前必须确保全部场次都有足够考官配岗。
- 评分一致性：MIX 模式的小组与个人记录需保持联动与一致。
- 安全与过滤：路由较宽松但配合 JWT 与过滤器；少量方法级 `@PreAuthorize`。
