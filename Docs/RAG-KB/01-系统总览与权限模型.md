# OAS 口语评估 · 系统总览与权限模型

## 目的与范围
本文概述 OAS 口语评估系统的整体架构、技术栈选型理由、各模块核心职责以及基于数据库的 RBAC 权限模型，并串联核心业务的数据流转，帮助理解系统设计的全局视图。

## 架构与技术栈
### 后端架构
- **框架核心**：Spring Boot + Spring Security。采用无状态架构，通过 JWT（JSON Web Token）进行身份验证，结合 Redis（或本地缓存）处理 Token 黑名单与防重放。
- **数据访问层**：MyBatis-Plus + MyBatis XML。
  - *选型理由*：相比 JPA，MyBatis 在处理复杂报表（如成绩汇总、趋势分析）和动态 SQL（如多条件组合查询）时具有更高的可控性与性能优势，便于 DBA 进行 SQL 调优。
- **安全体系**：
  - **过滤器链**：自定义 `XssFilter`（防 XSS 攻击）、`RepeatableFilter`（防表单重复提交）与 `JwtAuthenticationTokenFilter`（鉴权）。
  - **双 Token 机制**：Access Token（短效）+ Refresh Token（长效），兼顾安全与体验。

### 领域模块划分
1.  **预约与场次（Scheduling）**：处理高并发下的学生选课、时段切分与考官配岗。
2.  **评分与量规（Assessment）**：核心评分引擎，支持动态量规、MIX 模式双写联动。
3.  **成绩汇总（Consolidation）**：管理端仪表盘，提供实时进度、趋势分析与异常告警。
4.  **数据集成（Integration）**：Canvas 兼容的 CSV 导入导出管道。
5.  **基础设施（Infra）**：通知队列（邮件）、审计日志、文件存储。

## RBAC 权限模型
系统采用基于数据库的 RBAC（Role-Based Access Control）模型，而非硬编码权限。

### 核心实体关系
- **用户（SysUser）**：系统登录主体。
- **角色（SysRole）**：权限集合的载体（如 `admin`, `examiner`, `student`）。
- **菜单/权限（SysMenu）**：具体的资源标识（如 `system:user:list`）。
- **关联表**：`sys_user_role`（用户-角色多对多）、`sys_role_menu`（角色-权限多对多）。

### 预置角色与能力
1.  **超级管理员（SuperAdmin）**
    - *职责*：系统级配置、账号管理、审计日志查看。
    - *权限*：拥有 `*:*:*` 最高权限。
2.  **课程管理员（CourseAdmin）**
    - *职责*：作业生命周期管理。包括创建作业、配置时段、生成场次、分配考官、发布成绩、处理 CSV 导入导出。
    - *边界*：只能管理被授权的课程/作业。
3.  **考官（Examiner）**
    - *职责*：执行评估。查看分配的场次、对学生/小组进行评分（草稿/提交）。
    - *边界*：仅能看到自己被分配的场次和学生，不可见其他考官数据。
4.  **学生（Student）**
    - *职责*：参与评估。预约/改约场次、查看已发布的成绩与反馈。
    - *边界*：严格的数据隔离，仅可见自己的数据。

## 核心数据流（Lifecycle）
### 1. 预约与场次流转
- **配置期**：管理员定义 `TimeSlot`（大时段） -> 系统按规则切分为 `SlotSession`（小场次） -> 管理员为场次分配 `SysExaminer`。
- **发布期**：管理员执行“发布给学生” -> 系统校验“完全配岗” -> 状态流转为 `RELEASED` -> 锁定场次配置（不可变护栏）。
- **预约期**：学生查询可用场次 -> 发起预约 -> 系统执行乐观锁扣减容量 -> 生成 `SessionStudent` 记录。

### 2. 评分与成绩流转
- **评估期**：考官拉取待办 -> 填写评分（Draft） -> 提交评分（Submitted） -> 系统计算总分并写入 `AssessmentSubmission`。
- **MIX 联动**：若为混合模式，提交小组分时，系统自动计算并更新组内所有成员的个人分记录。
- **发布期**：管理员在仪表盘确认进度 -> 执行“发布成绩” -> 系统发送通知邮件 -> 学生端可见成绩与反馈。
